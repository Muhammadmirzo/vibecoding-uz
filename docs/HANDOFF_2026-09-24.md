## 2. ⚠️ Action required (in priority order)

### 2.1 Database is unreachable — BLOCKER for all DB features
The production `DATABASE_URL` points to Supabase project `gvfzomtdswzlxstjvwiv`, whose host **no longer resolves** (pooler: "tenant/user not found" in every region). The project was likely **paused or deleted**. This was already the case before this deploy.
Affected until fixed: login/OTP, cabinet, admin/CRM, lead & quiz submissions, payments, certificates, blog posts from DB.

**Fix:**
1. Supabase dashboard → restore/unpause the project (or create a new one).
2. Update `DATABASE_URL` in Vercel (`master-2` → Settings → Environment Variables) if the URL changed. Use the **Session pooler** URL shown in Supabase → Connect.
3. Apply migrations from your machine:
   ```bash
   vercel env pull .env --environment=production --yes
   npm run db:migrate          # applies drizzle/0001…0003
   ```
   Note: `0001_daily_tarot` (leads) may already exist on the old DB. If `db:migrate` fails with "already exists", mark 0001 as applied in `drizzle.__drizzle_migrations` and re-run. `0003` (`ALTER TYPE payment_status ADD VALUE 'cancelled'`) is intentionally separate because Postgres doesn't allow it inside a transaction.
   On a **new empty** DB, also run `npm run db:seed` and `npm run admin:create`.
4. Redeploy: `vercel --prod` or push any commit to `main`.

### 2.2 Register the Telegram webhook secret — ✅ DONE for @Boyakagabot (kept for reference)
New env vars were added to Vercel production: `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_LINK_SECRET`, `CRON_SECRET` (random 256-bit values; view them in Vercel). The webhook now **rejects** requests without the secret header, so re-register the webhook once:
```bash
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -d "url=https://<your-domain>/api/telegram/webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```
Old `/start <UUID>` account-link links no longer work (by design: they were the takeover hole).
